# CyberDefenders Lab: RedLine Writeup

**Category:** Endpoint Forensics | **Tools:** Volatility 3, Linux CLI

---

### Q1: What is the name of the suspicious process?

*   **Approach:** Identify anomalous processes by examining the system's process tree.
*   **Steps Taken:** 
    *   Execute the command `python3 vol.py -f <FileCanPhanTich> windows.pstree` to list the processes in a tree format.
    *   The output reveals an unusual process named `oneetx.exe` running under PID 5896.
    *   This process is located in the `AppData\Temp` directory, which is frequently used by malicious executables.
    *   Furthermore, `oneetx.exe` spawns a child process named `rundll32.exe`. While `rundll32.exe` is a legitimate Windows DLL, it becomes highly suspicious when spawned by an unrecognized executable.
*   **Evidence:**
    ![Q1 - Process Tree showing oneetx.exe](images/q1.png)
*   **Flag:** `oneetx.exe`

### Q3: What is the memory protection applied to the suspicious process memory region?

*   **Approach:** Investigate the Virtual Address Descriptors (VAD) of the suspicious process to uncover details about its associated memory regions, including sizes, attributes, and protections.
*   **Steps Taken:** 
    *   Run the command `python3 vol.py -f <FileCanPhanTich> windows.vadinfo | grep 5896` to analyze the memory protection of the `oneetx.exe` process.
    *   Most returned VAD regions with `PAGE_EXECUTE_WRITECOPY` protection are normally associated with legitimate system DLL files (e.g., `\Windows\SysWOW64\AcLayers.dll`), which is standard for Windows memory mapping.
    *   However, an anomalous memory region is discovered at the base address `0x400000`, which is the default Image Base address for a 32-bit `.exe` file.
    *   This specific region carries the `PAGE_EXECUTE_READWRITE` protection (allowing simultaneous read, write, and execute permissions) and is not mapped to any actual file path on the disk.
    *   The combination of it being at the default base address, possessing RWX permissions, and lacking a mapped file path is a classic indicator of Process Hollowing or Code Injection. The original process code was hollowed out and overwritten with malicious shellcode.
*   **Evidence:**
    ![Q3 - PAGE_EXECUTE_READWRITE protection in VAD info](images/q3.png)
*   **Flag:** `PAGE_EXECUTE_READWRITE`

### Q4: What is the name of the process responsible for the VPN connection?

*   **Approach:** Identify network routing or VPN-related applications running on the system by checking the process tree.
*   **Steps Taken:** 
    *   Utilize the `python3 vol.py -f <FileCanPhanTich> windows.pstree` command once more.
    *   The output identifies a process named `tun2socks.exe` (PID 4628) with a parent process ID (PPID) of 6724.
    *   PID 6724 belongs to `Outline.exe`, which is an executable for a VPN/proxy application developed by Jigsaw.
    *   In this architecture, `Outline.exe` acts as the manager/controller for the VPN client, while `tun2socks.exe` handles receiving traffic from the TUN interface and forwarding it through the proxy/tunnel.
    *   Consequently, the primary process responsible for the VPN connection itself is `Outline.exe`.
*   **Evidence:**
    ![Q4 - Outline.exe and tun2socks.exe in process tree](images/q4.png)
*   **Flag:** `Outline.exe`

### Q5: What is the attacker's IP address?

*   **Approach:** Extract active network connections to identify external communication from the malicious process, revealing the source IP, destination IP, and ports.
*   **Steps Taken:** 
    *   Execute `python3 vol.py -f <FileCanPhanTich> windows.netscan` to view network connections.
    *   The plugin's output shows two suspicious network connections linked to `oneetx.exe` and `tun2socks.exe`.
    *   As established, `tun2socks.exe` is part of the legitimate `Outline.exe` VPN application, meaning its destination IP handles traffic forwarding via port 443 (HTTPS) and does not belong to the attacker.
    *   In contrast, the destination IP `77.91.124.20` is actively connected to the malicious `oneetx.exe` process via port 80 (HTTP).
    *   This indicates a high probability that `77.91.124.20` is the malicious IP address serving as the Command and Control (C2) server.
*   **Evidence:**
    ![Q5 - Network scan showing connection to 77.91.124.20](images/q5.png)
*   **Flag:** `77.91.124.20`

### Q6: What is the full URL of the PHP file that the attacker visited?

*   **Approach:** Extract the memory space of the malicious process and perform string analysis to find requested web URLs.
*   **Steps Taken:** 
    *   First, dump the entire memory associated with the suspicious process (PID 5896) using the command: `python3 vol.py -f RedLine.mem -o ./output windows.memmap --pid 5896 --dump`.
    *   Once the dump is complete, use the `strings` utility to list strings within the dumped file and filter for PHP extensions using `strings ./output/pid.5896.dmp | grep ".php"`.
    *   The output reveals that the attacker visited an `index.php` file, with the full URL being `http://77.91.124.20/store/games/index.php`.
*   **Evidence:**
    ![Q6 - Memory dump strings showing the PHP URL](images/q6.png)
*   **Flag:** `http://77.91.124.20/store/games/index.php`
